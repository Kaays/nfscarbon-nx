# nfscarbon-nx v0.3.0

Need for Speed: Carbon (Xbox 360) running natively on the Nintendo Switch. This release makes the game playable
from start to finish with an overclock: clean sound with the fourth CPU core, cutscene videos at normal speed,
and the cutscene and boss-box graphics bugs fixed.

> **Needs your own copy of Need for Speed: Carbon for Xbox 360, USA edition** (a `.iso` or the extracted disc with
> `default.xex`). No game files are included here.
>
> **Needs an overclock.** The game is CPU-bound and does not run well at the Switch's stock clocks. Everything
> below was tested at **CPU 1683 / GPU 844 / RAM 2133 MHz**.

## Files

- `nfscarbon.nro`: the port (profile-guided build)
- `nfscarbon.toml`: settings. **Replace your old one**: several defaults changed in this release.

## Install

You need a Switch running Atmosphère and a way to overclock it (for example sys-clk).

1. Download `nfscarbon.nro` and `nfscarbon.toml` below.
2. Put them on the SD card together with the files of your disc:

   ```text
   sdmc:/switch/nfscarbon-nx/
     nfscarbon.nro
     nfscarbon.toml
     game_root/        (the files of your disc: default.xex, NFS/, MOVIES/, ...)
   ```

   A `.iso` placed next to the NRO works too, instead of `game_root/`. To extract a disc image on a PC:
   `python3 tools/fase1_extraer.py path/to/game.iso -o game_root`.
3. Set the overclock: CPU **1683 MHz** or more, GPU **844 MHz**, RAM **2133 MHz**. More CPU clock helps further.
4. Start the game in one of two ways:
   - **Recommended: a forwarder with four CPU cores** (see the next section). This gives the cleanest sound and the
     best frame rate.
   - **Title takeover**: hold **R** while starting any installed game, then pick `nfscarbon.nro`. This works too,
     but uses three cores, so the start of Race Wars is slower and the sound pops a little there.

   Album (applet) mode does not give the game enough memory and will not work.

The first race stutters while graphics pipelines are compiled. They are saved on the SD card
(`cache/carbon_gpu`), so later sessions start smoothly. Saves go to `nfscarbon/` next to the NRO, logs to
`logs/`.

## Enable the fourth CPU core (recommended)

A Switch game normally runs on three of the console's four CPU cores; the fourth is kept for the system. The port
can use the fourth one too, and at the start of Race Wars, where the CPU is fully busy, that is the difference
between broken-up sound and clean sound. The core count is set by the launcher, so this needs a HOME Menu
forwarder:

1. Install [Sphaira](https://github.com/ITotalJustice/sphaira) if you don't have it.
2. In Sphaira's homebrew list, select `nfscarbon.nro` and install a forwarder for it.
3. In the forwarder options, set the **CPU core count to 4**.
4. Start the game from the new icon on the HOME Menu (no need to hold R).

If you already had a forwarder for nfscarbon-nx, delete it first and install it again with 4 cores. Your game
files, saves and settings on the SD card are not touched.

To check that it worked, open `sdmc:/switch/nfscarbon-nx/logs/rex/rex_perfil.log` after playing: it should say
`nucleos del proceso 4 (mascara 0xF)`.

Using another forwarder tool? Patch the forwarder's `main.npdm` with
`python3 tools/npdm_core3.py main.npdm -o main.npdm.core3` (from the source repository) and put the result at
`sdmc:/atmosphere/contents/<forwarder title id>/exefs/main.npdm`.

The fourth core is shared with the system (HOME Menu, overlays, background services). It has worked fine in our
tests, but long sessions have not been tested much: please report anything odd.

## Performance (Switch Lite, CPU 1683 / GPU 844 / RAM 2133)

| | Four cores (forwarder) | Three cores (title takeover) |
|---|---|---|
| Menus, free roam, cutscenes | 30 FPS | 30 FPS |
| Normal races, canyon duels, police chases | 28-30 FPS | 28-30 FPS |
| Race Wars, first seconds (whole pack on screen) | 24-27 FPS, then 28-30 | 19-24 FPS for 20-40 s, then 26-30 |
| Sound | clean | some popping at Race Wars starts |

The game is locked to 30 FPS by design, as on the Xbox 360.

## What's new since v0.2.0

**Fourth CPU core**
- The game's threads now run on every core the process is given. With four cores, the lost audio blocks at the
  start of Race Wars went from 59-179 per 10 seconds to none. Thanks to the player who reported it in #1.

**Videos**
- Cutscene videos and the boss face videos are decoded with FFmpeg's WMV3 decoder (ported from zofo007's
  NFS-Carbon-NX). They now play at normal speed.

**Graphics fixes**
- In-car cutscenes (boss confrontations, Neville's garage): the people behind the car windows no longer
  disappear.
- The boss picture-in-picture box now runs at full frame rate instead of looking choppy.
- The vertex cache is now 256 MiB. At 128 MiB it filled up in crowded races and started over, which made the white
  flash much more frequent.
- Together these cost less than 1 FPS.

**Sound and CPU**
- More of the audio server's hot loops run as native code (ramped mixing, sample unpacking), checked to give
  exactly the same output as the original code.
- New optional setting `nfscarbon_lod_bias` (from NFS-Carbon-NX): below 1.0 (for example 0.8), small far objects
  drop out sooner and crowded scenes draw less. Default 1.0, the game's own detail.

**Building from source**
- The full build no longer takes over an hour on some machines.

## Known issues

- The car's shadow slides behind the car at speed (it sits under the car when slow). Most visible in Race Wars.
- A rare one-frame white flash in long races. Once in a while, a few black frames at a race start.
- A short freeze when you take control at the start of a race.
- The first race stutters while pipelines are compiled (only the first time).
- Only the USA edition is supported.

## Reporting problems

Please [open an issue](../../issues) and attach `logs/nfscarbon_*.log` and `logs/rex/rex_perfil.log` from
`sdmc:/switch/nfscarbon-nx/`. For a crash, add `logs/rex/rex_crash.log` and the Atmosphère report from
`sdmc:/atmosphere/crash_reports/`. Say which clocks you used and whether the fourth core was enabled.
